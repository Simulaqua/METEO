# Radar-DPC rilascio 2 "Tutte le mappe" Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 23 prodotti Radar-DPC sulla mappa con menu "Mappa" e interruttore "Stazioni".

**Architecture:** `dati_radar.py` diventa un elenco di prodotti (stessa griglia di uscita, palette per prodotto nel
manifest, push incrementale del branch `radar`); `site/radar.js` legge prodotti e palette dal manifest; `index.html`
aggiunge menu, interruttore e accoppiamento dei puntini per prodotto.

**Tech Stack:** come il rilascio 1 (Python 3.7/numpy 1.16/Pillow 5.4/git 2.20 sul Pi; JS + Leaflet 1.9.4).

**Spec:** `docs/superpowers/specs/2026-10-22-radar-dpc-r2-design.md` (e quella del rilascio 1 per la base).

## Global Constraints

- Vincoli del rilascio 1 (Pi, nomi, griglia 773×517, UTC nei nomi, niente commit locali, niente deploy.sh, patch sul Pi
  con file nuovo + mv / rsync, mai riscritture sul posto di script in esecuzione).
- PNG: classi = n. soglie ≤ valore; se `colors[0] == ''` il "nessun dato" va nella classe 0 (layout identico al rilascio 1,
  tRNS = 0); altrimenti "nessun dato" = indice N+1 e tRNS a byte (alpha 0 per i colori vuoti e per N+1).
- Sentinelle: valore non finito o ≤ -9000 = nessun dato.
- Cadenze: 5 min tutti tranne CAPPI 10 min, IR108 15 min, CUM 30 min, TEMP 60 min; finestra 6 h.
- Budget per giro 240 s; prima il fotogramma più recente di ciascun prodotto, a turno.
- Compatibilità: `products.SRI` nel manifest, `read_sri`, `frame_name(t)`, `load_or_build_lut(dir, grid)` restano.

## Review Focus

1. CUM48 quando manca CUM24(t-24 h) (oltre i 14 giorni o 404) → fotogramma CUM48 mancante, gli altri prodotti avanti (Task 3).
2. Prodotto che il DPC smette di dare (404 su findLast) → resta l'ultimo stato pubblicato degli altri, nessun crash (Task 3).
3. Compattazione giornaliera mentre un push è fallito → al giro dopo ripubblica tutto (Task 4).
4. Cambio prodotto mentre la barra è in riproduzione → stesso istante, niente salti (Task 6).
5. Prodotto senza puntini + utente che sceglie una variabile → radar spento, come nel rilascio 1 (Task 7).
