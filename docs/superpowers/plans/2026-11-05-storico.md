# Storico — piano (punto 3 di 5)

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development. Steps use checkbox (`- [ ]`) syntax.

**Goal:** the long history ("Storico", release 3: daily rain and temperature for every station, from the whole
archive) is verified on real data, pinned by tests, and ready to be switched on at the program's final publish.

**Architecture:** history.py (aggregates per station and solar day, cache, output files + index.json) and
publish_history.sh (orphan force-push of the output to branch `history`, once a day at 07:20) exist since October;
the page shows a "Storico" button only when `<history>/index.json` lists the station's region. This plan adds the
missing safety nets (Python tests of the aggregates, a browser suite of the Storico views) and fixes what the trial
run on real data shows. Switching it on (cron line + first run + live check) happens at the final publish.

**Tech Stack:** Python 3.7 (Pi), quality.py filters, the single-page site (site/index.html, uPlot), headless Chrome
suites (tests/web).

**Spec:** the October design in memory/dashboard roadmap (release 3) and the code's own header; no separate spec.

## Review Focus

1. A day counts as complete only with enough hours of data; a station-day with no data is `null`, not 0.
2. The solar day (UTC+1 all year) bounds every aggregate, also on the October/March DST change days.
3. VEN: where the old archive and the new one overlap, the day with more hours wins, never a mix of both.
4. The cache: a second run recomputes only new days + the last 3, and gives the same files as a full run.
5. The page: the button appears only for regions listed in index.json and only for PREC/TEMP; every view renders
   with long series (years) at phone width.
